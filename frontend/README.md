# FRAME — конкурсное AI-демо

Интерактивный прототип продукта для управления ремонтом. Главный демо-сценарий: AI снижает потери из-за несогласованных изменений бюджета и решений, затерявшихся в переписке.

## Что показывать

1. `/ai` — единая очередь решений по проекту и помощник с источниками.
2. `/messages` — AI-координатор превращает цепочку сообщений в карточку события, которую подтверждает человек.
3. `/estimates` — объяснимая сверка 13 из 14 позиций с медианными рыночными ориентирами.

Остальные разделы нужны только как продуктовый контекст и не должны занимать основное время защиты.

## Режимы работы

Демо умеет работать и вживую, и полностью офлайн. Режим **всегда виден в интерфейсе**
и никогда не подменяется молча.

| Режим | Когда возникает | Что значит |
|---|---|---|
| `LIVE_HYBRID` | backend доступен, GigaChat Embeddings и extraction отработали | реальный вызов модели |
| `PARTIAL_HYBRID` | часть окон диалога разобрана LLM, часть — правилами | смешанный прогон |
| `RULES_ONLY` | нет ключа или LLM недоступна | честный детерминированный fallback |
| `DEMO_FIXTURE` | backend офлайн | заранее подготовленная карточка, помечена явно |

Живой разбор подключён к ветке «Старая проводка на кухне — доплата» на `/messages`.
Кнопка «Проанализировать переписку» отправляет цепочку в backend и показывает
фактические `retrieval_backend`, `extraction_backend` и время ответа.

## Что показывать

1. `/ai` — очередь решений, журнал подтверждений и помощник с источниками.
2. `/messages` — живой разбор цепочки в карточку `budget_change` с источниками `#1–#4`.
3. `/estimates` — сверка 13 из 14 позиций с медианными ориентирами.

## Запуск

Из корня репозитория сначала запустите backend:

```bash
python src/demo_api.py
```

Во втором терминале:

```bash
cd frontend
npm ci && npm run dev
```

Демо: `http://127.0.0.1:5174/ai`, API:
`http://127.0.0.1:8000/api/health`.

Ключ провайдера живёт только в корневом `.env` (см. корневой `.env.example`).
Во frontend секретов нет: настраивается только `VITE_API_BASE`.

Проверки:

```bash
npm run lint
npm run build
```

## Честные ограничения

- Ценовая сверка использует **медианный ориентир и коридор**, а не предсказание
  линейной модели: при LOCO-проверке на новой компании модель не улучшила MAPE
  baseline (44.0% против 43.5%).
- Метрики координатора получены на **авторском синтетическом корпусе**
  (45 сообщений, 19 событий) и проверяют работоспособность пайплайна,
  а не продуктовую точность.
- Аспектный рейтинг подрядчиков остаётся **R&D**: quality gate не пройден.
- Формулировки «справедливая цена», «переплата», «завышение» не используются:
  результат сверки — повод для вопроса подрядчику.
